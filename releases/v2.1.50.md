
# Release 2.1.50 (2026-11-09)

## Bug fixes

- **run the template-generation, provision-manifest and rootless-userns checks in validate-custom (#375) (#388)**
These three host-side checks ran only from tests/run-host-tests.sh, which only scripts/build.sh calls, and build.sh needs Lima. So vrg-validate and the PR CI quality / custom job never ran them, and a hand-edited or stale templates/agent.yaml passed both. Add them to the validate-custom check loop. None of them needs Lima or tofu. The loop now has a comment saying to keep it in step with run-host-tests.sh. The tofu-missing behaviour is unchanged.

- **install git explicitly on the agent VM (#389)**
10-base.sh now apt-installs git instead of relying on the base image to carry it, so the Stage 1 table in the architecture docs is true. templates/agent.yaml and the Azure and GCP cloud-init.yaml files are regenerated from the provision scripts. Ref #387.

- **clear the shellcheck findings across every *.sh file (#392)**
vrg-validate now shellchecks every *.sh file (vergil-tooling 2.1.289). Fix the real findings (split declare-and-export, parameter expansion instead of echo|sed, and make the three negated grep assertions in test_base.sh fail under errexit) and add targeted, reasoned disables for the guest-only provision.env source and the deliberate literal $ strings. Regenerate agent.yaml and the cloud-init files. Ref #391.

- **sync guard.sh with vergil-tooling's packaged hook guard shim (#393)**
Replace the old copy of .claude/hooks/guard.sh with vergil-tooling's packaged shim (src/vergil_tooling/data/hook_guard_shim.sh on develop), byte for byte. The fallback now fails closed when jq is missing or the hook input cannot be checked, and passes non-Bash tool calls through, matching vrg-hook-guard. Ref #390.

- **pin agent VMs to Ubuntu 24.04 (#396)**
* fix(lima): pin agent VMs to Ubuntu 24.04

* fix(lima): regenerate cloud-init for the racc seed comment
