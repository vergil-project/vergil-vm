
# Release 2.1.51 (2026-11-10)

## Bug fixes

- **provision buildkitd with the containerd worker in namespace default (#400) (#401)**
install-buildkit's OCI worker keeps its own content store, so nerdctl build could not use a locally built image as a parent (FROM <local> resolved against docker.io: pull access denied). 35-buildkit.sh now runs CONTAINERD_NAMESPACE=default install-buildkit-containerd, giving one default-buildkit.service on the buildkit-default socket nerdctl probes first. On Lima that unit already exists (Lima installs it), which is why the bug only showed on cloud VMs; the setuptool skips it.

test_services asserts default-buildkit; the readiness probe requires a containerd-worker buildkitd in namespace default, with bracketed pgrep patterns so the probe's own bash -c no longer self-matches (it always passed before). test_containerd checks the worker and socket, then builds and runs an image FROM the locally built test image. Design doc #97 records the revision. Regenerated agent.yaml and the cloud-init files.
