## Features

- **default interactive shells to a separate .venv-host uv env (#206)**
Agent development runs inside the container (vrg-container-run), which builds and owns the project's default .venv. A uv/virtualenv hard-codes the absolute paths of whatever created it, so that container-built .venv is not reusable from an interactive host shell — humans and agents doing interactive/worktree work outside the container clobbered .venv and hit constant path conflicts.

Export UV_PROJECT_ENVIRONMENT=.venv-host from the base VM's interactive shell startup (~/.zshrc), so every Vergil-built VM points interactive uv at its own host-side environment while the container keeps using .venv. The split is clean in both directions: ~/.zshrc is interactive-only (not ~/.zshenv, which would leak onto non-interactive host paths), and vrg-container-run forwards only repo-allowlisted env prefixes, so the variable never reaches the container. UV_CACHE_DIR is intentionally left unset — uv's cache is content-addressed and the container's cache is isolated, so there is no collision to split.

Lives in global VM provisioning, so it applies to all VMs with no per-repo vergil.toml changes. Regenerates the Lima template and GCP cloud-init that embed the provision scripts; adds a test_base.sh assertion for the .zshrc mechanism (and that it is absent from .zshenv).

- **IAP-based access for the GCP vm module (#207) (#211)**
Replace the public-IP + operator-IP-allow-list SSH model with GCP Identity-Aware Proxy (IAP) TCP tunneling. The old model was unsound behind NAT: a host cannot self-detect its public IP without a third-party echo — an unacceptable dependency in a security-critical, create-blocking path.

- Drop access_config from the instance (no ephemeral public IP).
- Set the SSH firewall source_ranges to Google's fixed IAP range 35.235.240.0/20 (a module constant, not an operator address).
- Retire ssh_public_key and ssh_source_ranges; gcloud --tunnel-through-iap provisions ephemeral keys, so the module manages no keypair. interface.json contract change.
- Rework the host output to the instance name (IAP addresses the box by instance name + zone; the consumer already holds the zone).
- Document the IAP model and the operator-account precondition (IAP API enabled, roles/iap.tunnelResourceAccessor granted; #204).

- **publish opentofu modules as release asset, drop prevent_destroy (#212)**
Off-platform vrg-vm fetches the OpenTofu modules with a single unauthenticated GET of a release asset (the cloud analog of the raw agent.yaml fetch). Add a bespoke publish-modules job to cd.yml: after cd-release cuts the release, it tars the opentofu/ subtree into opentofu-modules-$VERSION.tar.gz and uploads it to the v$VERSION release. A reusable-workflow uses: job can't carry its own steps and cd-release has no build step for non-language repos, so packaging is a local job rather than a release-artifacts param.

Remove prevent_destroy from google_compute_disk.data: a literal can't be conditionalized, so it blocks the legitimate destroy-volume verb. The two-state separation (routine destroy targets vm state only) plus the confirmation-gated destroy-volume verb are the real guard. Update the ADR to match.
