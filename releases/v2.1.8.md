
# Release 2.1.8 (2026-06-04)

## Documentation

- **add per-repo VM profiles design spec (#99)**
Two-file, two-cascade model for multiple VMs per identity: repo vergil.toml [vm] (role cascade) declares requirements; identities.toml holds credentials, base footprint, host overrides. Existence of config decides base vs dedicated; reversible double-dash instance naming; composed-spec fingerprint drives the NEEDS-REBUILD drift gate; list gains CPUS/MEM/DISK and AGENTS/HUMANS occupancy. Supersedes the issue's Fork B profile-name sketch.

- **fold pushback resolutions into VM profiles spec (#99)**
Apply the structured pushback review: normalize identity keys to vergil-<role> (migration section); tunable stale_days (lab=7); process-tree AGENTS/HUMANS counting; soften reproducibility to declared-spec; security-boundaries section + register issue vergil-tooling#1369; orphaned dedicated-VM lifecycle; loud under-provisioning warning; provision hook is tooling-only (lab building is dev-time); defer #97 buildkit.

- **add Plan 1 (spec foundation) for per-repo VM profiles (#99)**
First of three dependency-ordered implementation plans: parsing the repo [vm] cascade, host-override tables, the five-tier compose_vm_spec, reversible -- instance naming, and the declaration fingerprint — all pure logic in vergil-tooling, fully unit-tested. Plans 2 (lifecycle/CLI) and 3 (observability) build on its frozen API.

- **add Plans 2 (lifecycle) and 3 (observability) for VM profiles (#99)**
Plan 2: agent.yaml param provisioning (packages/hook/fingerprint marker), create_vm threading, fingerprint drift helpers, _resolve_target base-vs-dedicated, create/rebuild branching, session/start abort gate + tunable staleness + under-warning, lifecycle positionals. Plan 3: process-tree vm_occupancy, discover_dedicated (present/orphaned/not-created), rewritten list view with CPUS/MEM/DISK/AGENTS/HUMANS/SPEC, orphan-aware destroy. Completes the three-plan set.

- **apply alignment fixes to VM profile plans (#99)**
Finding 1: thread provision_hash through ComposedSpec (Plan 1), fingerprint over the hook's CONTENTS not its path (Plan 1 Task 5), and read+SHA the hook in _resolve_target (Plan 2 Task 4) so editing provision.sh flips NEEDS-REBUILD — delivering the spec's security review-checkpoint. Finding 2: add Plan 2 Task 8, an end-to-end CI build test (tiny profile: package + hook + fingerprint marker), realizing the spec's end-to-end acceptance criterion.

- **use vrg-validate as the per-task verification gate in plans (#99)**
Repo policy mandates vrg-validate as the only validation command; replace the plans' per-step direct-pytest verification with a single per-task vrg-validate green gate.


## Features

- **layer profile packages, hook, and fingerprint at provision time (#99)**
Add a param-driven provisioning step (EXTRA_PACKAGES/PROVISION_HOOK/SPEC_FINGERPRINT): stamp /etc/vergil/vm-spec.fingerprint, install additive apt packages, run the repo provision hook (tooling only). All no-ops when params are empty, so the base box is unchanged. In-guest test_vm_profile.sh asserts the marker is stamped.


## Testing

- **end-to-end profile build: package + hook + fingerprint (#99)**
tests/e2e-vm-profile.sh builds a tiny parameterized VM (cowsay + sentinel hook + test fingerprint) via the template params and asserts all three landed in the VM — the spec's end-to-end acceptance criterion. Wired into scripts/build.sh after the base test run. Named non-test_* so run-tests.sh does not run it in-guest.
