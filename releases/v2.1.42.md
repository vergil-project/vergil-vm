## Features

- **boot_disk_type variable on the vm modules (#312) (#313)**
Add boot_disk_type to the interface contract and both vm modules so consumers can choose faster storage for the ephemeral boot disk.

GCP sets boot_disk.initialize_params.type. The default is null, which omits the field and keeps today's behaviour: GCE picks the machine series' default (pd-standard on N1/N2, pd-balanced on C3, hyperdisk-balanced on C4/N4 and newer, per the Compute Engine API reference). A literal pd-standard default would break series that do not support Standard PD. Allowed: pd-standard, pd-balanced, pd-ssd, hyperdisk-balanced.

Azure sets os_disk.storage_account_type, defaulting to the previously hard-coded StandardSSD_LRS, with the azurerm-documented SKUs as the allowed set. interface.json requires every provider to declare the variable.

Both fields are ForceNew, so changing the value replaces the instance; that is acceptable because the boot disk is ephemeral. Documented in the off-platform modules decision page.
