
# Release 2.1.6 (2026-06-01)

## Bug fixes

- **drop redundant template pre-validation**
limactl validate has no --set, so it rejected the HOST_PROJECTS_DIR placeholder that the create step resolves via --set. limactl create validates the effective merged config, so the standalone pre-check was redundant and broke the build under limactl 2.1.1.

- **make runner robust for user-service tests**
Two harness fixes: (1) export XDG_RUNTIME_DIR=/run/user/$(id -u) in-guest before each test so systemctl --user reaches the rootless-containerd user bus (was 'No medium found' under the non-login pipe shell); (2) guard the diagnostic re-run with || true so set -e -o pipefail no longer aborts the runner after the first failing test, letting all tests run and a summary print.

- **unbreak vergil and credentials tests on clean build**
test_vergil asserted vrg-docker-run, renamed upstream to vrg-container-run. test_credentials now skips gracefully when no credentials are provisioned (the automated build never runs vrg-vm-init); it still validates layout on the manual credentialed gate. Baseline suite is now green end to end.

- **resolve ~/.local/bin in non-login shells**
uv and uv-installed vergil tooling land in ~/.local/bin, but Claude Code's non-interactive shells (limactl shell -- ...) don't source ~/.zshrc or /etc/profile.d — their PATH comes solely from /etc/environment via PAM. Prepend ~/.local/bin there (resolving the real home via getent, since Lima may suffix it as <user>.guest) and drop the now-stale /snap/bin left by the snapd purge.

- **count only live timers in metrics**
list-timers --all renders masked timers as dead rows (no NEXT/ACTIVATES), so the masked units we just stripped still counted toward the surface — the before/after timer delta read as ~0 despite real reductions. Drop --all so the snapshot counts only live/scheduled timers, making the delta meaningful.

- **parse identities.toml with tomllib, not host yq**
vrg-vm-init read identity credentials via 'yq', which (a) isn't a host dependency and (b) defaults to YAML input, so it never parsed the TOML config even when installed. The error was swallowed by '|| true', surfacing as a misleading 'app_id not found'. Replace with a tomllib parse (stdlib, Python 3.11+) that exits non-zero with a clear message on a parse error or missing field — no fallback that masks bad config.

- **fail loud on mask/purge errors instead of swallowing them**
The minimization block swallowed real failures: 'systemctl mask $u || true' (gated by systemctl cat, so a present unit failing to mask was a real anomaly) and 'apt-get purge ... 2>/dev/null || true' / autoremove. apt-get exits 0 when there is nothing to remove, so the || true never aided idempotency — it only hid a genuine purge failure and would ship a VM that still has snapd, with no test backstop in a real user create. Drop the swallows so set -e aborts provisioning visibly. Verified: full rebuild provisions cleanly (all 31 units mask, snapd/unattended-upgrades purged) with 7/7 in-guest tests green.


## Documentation

- **add stale-session lifecycle design**
Design for age-aware resume, --fresh with archive-via-relabel (append an archived agent-name to the cold transcript; never delete), list --sessions state filters + last-active age column, and a configurable session_stale_days (default 7). Pairs with vergil-tooling #1323. Ref #82.

- **refine stale-lifecycle design after pushback review**
Pushback findings: (1) verified the relabel-archive mechanism live (Claude last-wins; safe append) and fixed the false 'parser naturally rejects archived@' claim — parse_name needs an explicit archived@ guard; (2) resume the most-recently-active idle slot, not lowest-numbered; (3) add a second threshold (session_archive_days, default 14) with a connection-time auto-archive sweep of stale cold slots; (4) tail-read the last timestamped entry for age (mtime untrusted on virtiofs); plus cold-safety invariant and a known-behavior note. Ref #82.

- **deterministic session naming design (#73)**
Capture the design for slot-indexed, deterministic Claude Code session naming and auto-resume in vrg-vm session, tying in the default-to-claude change (vergil-tooling #1292). Records the discovered prerequisite mount bug: the VM's .claude projects/sessions are mounted at the host path rather than the VM HOME, so session history is lost on rebuild. Detection mechanics under shared sessions are deferred to a live re-inspection after the mount fix and rebuild.

- **finalize session-naming detection design after live re-inspection**
Prerequisite mount fixes have landed (projects/skills symlinked, sessions kept VM-local) and detection was re-inspected live post-rebuild. Resolve the deferred open items: VM-local roster dissolves PID ambiguity, filename collision, and platform tagging. Record the EXDEV rationale for keeping sessions VM-local, the confirmed agent-name entry shape, and that the roster carries name. Mark plan-of-work steps 1-4 done. Ref #73.

- **add comprehensive vrg-vm session user guide**
Full session workflow: deterministic naming, most-recent resume, slots, --model cascade, list --sessions states/age, stale lifecycle (warn/auto-archive/--fresh, archive-never-delete), fork guardrail, /clear-vs-fresh, escape hatches, examples. New Sessions nav entry; cross-linked from Getting Started. Ref #81.

- **add VM service-surface minimization design**
Design for #78: systematic audit and minimization of the agent VM's systemd service surface. Defines the audit methodology, a candidate keep/mask/purge table grounded in Ubuntu 24.04 cloud-image defaults, mask-default + curated-purge mechanism, and durable guardrails (an intent-asserting test_services.sh and a dumb audit-services.sh).

- **add before/after footprint metrics to minimization design**
Adds scripts/vm-metrics.sh: a labeled before/after footprint snapshot (process count, idle memory, root-fs usage, unit counts) so the minimization win is quantified rather than asserted. Captures baseline on the unmodified image before any template change; gate stays the deterministic unit-count drop, with process/memory/disk as the win story and boot time as corroborating evidence.

- **incorporate pushback review into minimization design**
Applies five pushback findings: (1) add lima-guestagent/lima-* to the KEEP table plus a namespace rule, since masking Lima's own units silently breaks limactl access; (2) define the script execution model as host-side wrappers over one shared in-guest inventory snippet (tests/lib/inventory.sh) so audit/metrics/test cannot drift; (3) add an explicit security note that purging unattended-upgrades removes auto-patching, justified by the ephemeral-rebuild strategy and linked to the stale-session lifecycle; (4) require before/after resource-config parity with config recorded in the vm-metrics.sh header; (5) drop the inaccurate run-tests.sh registration touchpoint (tests are auto-discovered by glob).

- **reserve in-VM egress-filtering path in minimization design**
Egress filtering (vergil-tooling #901, three-layer iptables/HAProxy/pf, adopted from corral) is planned and pre-release-critical. Its only in-VM component is Layer 1 (iptables DNAT, persisted via netfilter-persistent). Adds a Forward-compatibility section and a namespace rule reserving all netfilter/iptables/nftables units as KEEP, and annotates systemd-resolved (DNS path constrained when Layer 3 drops port 53) and systemd-networkd (DNAT target derived from default route) with their egress rationale. Documentation only; no template change now, so the audit's keep/mask/purge decisions are made with egress in view. Also records an observation that #901 Task 4 omits enabling netfilter-persistent.

- **add VM service-surface minimization implementation plan**
Task-by-task TDD plan for issue #78: shared inventory snippet + audit/metrics host wrappers, a reconciliation gate that confirms the mask/purge lists against a real build, an intent-asserting regression test (red against the unstripped image), the template minimization block (green after rebuild), and before/after footprint evidence. Reserves lima-* and netfilter* units for egress filtering.

- **align plan and spec after alignment review**
Resolves four intent/action misalignments: (1) split the 'real Claude session end to end' acceptance into an automated smoke tier (uncredentialed build.sh) plus a manual credentialed end-to-end gate, since the test VM has no credentials; (2) add a per-unit keep/mask/purge decision table so every enabled/running unit gets a documented decision, not just changed units; (3) add a narrow regression assertion that the Lima guest-agent unit stays unmasked (netfilter units remain documentation-guarded until egress lands); (4) record that the spec-touching plan steps are planning-discovered accuracy fixes, not scope creep.

- **mark service-surface minimization implemented**
Implementation landed under issue #78: 31 units masked, snapd and unattended-upgrades purged, enabled units reduced 78 to 39. Verified against a rebooted stripped vergil-agent-test VM (7/7 in-guest tests green).


## Features

- **add shared in-guest inventory snippet**
Single source of truth for counting/dumping the systemd surface, consumed by the audit and metrics wrappers. Corrects the spec execution model: the test asserts unit states, not counts.

- **add audit-services.sh inventory dump**
Host-side wrapper over the shared in-guest snippet; dumps running services, enabled units, timers, sockets, and boot analysis.

- **add vm-metrics.sh footprint snapshot**
Host-side wrapper; labeled before/after footprint (proc count, idle memory, root-fs usage, unit counts) with resource config recorded in the header for parity.

- **minimize systemd service surface**
Dedicated mode:system block masks ~31 VM-irrelevant units (VMware tools, iSCSI, multipathd, udisks2, ModemManager, apport, Ubuntu Pro, sysstat, fwupd, mdadm, update-notifier, lxd-installer, motd-news, apt-daily timers, getty@tty1, networkd-wait-online) and purges snapd + unattended-upgrades. mask_if_present gates on systemctl cat so absent units are skipped. Comment header carries the keep/mask/purge table; reserves lima-* and netfilter*/ufw for egress filtering (#901). Mask/purge lists match tests/test_services.sh exactly. Closes the surface #74 warned about.
